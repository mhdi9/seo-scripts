# تشخیص حرکت اطراف موتور

این برنامه ویدئوها را برای بازبینی انسانی اولویت‌بندی می‌کند؛ تشخیص آسیب، قصد یا هویت افراد انجام نمی‌دهد. تمام پردازش آفلاین است و فایل‌های اصلی تغییر نمی‌کنند.

## نصب و اجرا در ترمینال VS Code

پایتون ۳٫۱۱ یا ۳٫۱۲ نسخه ۶۴ بیتی نصب کنید. هنگام نصب گزینه Add Python to PATH را فعال کنید. فایل‌های این پروژه را در یک پوشه نگه دارید و همان پوشه را در VS Code باز کنید.

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe motorcycle_monitor.py
```

اگر دستور `py` شناخته نشد، پس از نصب پایتون، VS Code را ببندید و باز کنید؛ می‌توانید `python` را هم امتحان کنید. نیازی به فعال‌کردن محیط مجازی یا تغییر Execution Policy نیست. نصب پکیج‌ها اینترنت می‌خواهد؛ پردازش ویدئوها اینترنت نمی‌خواهد.

۱. مسیر پوشه مادر ویدئوها را در ترمینال وارد کنید؛ فاصله و حروف فارسی مجاز است.

۲. در اولین اجرا مسیر یک ویدئوی نمونه را وارد کنید؛ Enter اولین فایل را انتخاب می‌کند.

۳. با ماوس یک مستطیل شامل موتور و فضای اطرافش بکشید و Enter بزنید. انتخاب ذخیره می‌شود.

۴. پردازش آغاز می‌شود. Ctrl+C پردازش را متوقف می‌کند؛ اجرای دوباره فایل‌های ثبت‌شده را رد می‌کند و ویدئوی نیمه‌تمام را از ابتدا بررسی می‌کند.

## محل خروجی

خروجی دقیقاً داخل پوشه‌ای که وارد کرده‌اید ساخته می‌شود:

```text
INPUT/okam_analysis/
    HIGH_PRIORITY/<original subfolders>/videos/
    HIGH_PRIORITY/<original subfolders>/screenshots/
    REVIEW/<original subfolders>/videos/
    REVIEW/<original subfolders>/screenshots/
    reports/analysis_report.csv
    reports/analysis_report.xlsx
    config/settings.json
    config/roi_config.json
    processing_state.sqlite3
```

پوشه خروجی از جست‌وجو حذف می‌شود. کلیپ‌های مشکوک بدون تبدیل یا افت کیفیت کپی می‌شوند. پسوند شناسه به نام خروجی افزوده می‌شود تا نام‌های تکراری برخورد نکنند. تاریخ گزارش از نام اولین زیرپوشه گرفته می‌شود؛ اگر فایل مستقیماً در ورودی باشد تاریخ خالی است. ترتیب پردازش براساس مسیر و نام است، بنابراین پوشه‌های YYYYMMDD به ترتیب تاریخ پردازش می‌شوند؛ زمان ضبط از تصویر استخراج نمی‌شود.

گزارش حاوی زمان رویدادها برحسب ثانیه از شروع کلیپ است. جزئیات تمام رویدادها در Events JSON ثبت می‌شود. از هر رویداد یک تصویر و حداکثر ۸ تصویر از قوی‌ترین رویدادهای هر کلیپ ذخیره می‌شود. نبود حرکت معنی‌دار باعث کپی‌نشدن ویدئو می‌شود. فایل خراب یا رزولوشن ناسازگار با وضعیت Failed در گزارش می‌آید و برای آن ممکن است تصویر یا کپی ایجاد نشده باشد؛ حتماً این ردیف‌ها را جداگانه بررسی کنید.

## تنظیم حساسیت و دوربین

```powershell
.\.venv\Scripts\python.exe motorcycle_monitor.py --sensitivity high
.\.venv\Scripts\python.exe motorcycle_monitor.py --edit-roi
.\.venv\Scripts\python.exe motorcycle_monitor.py --profile camera2
.\.venv\Scripts\python.exe motorcycle_monitor.py --retry-failed
```

هر بار تنها پوشه ویدئوهای یک نمای دوربین را وارد کنید. دوربین‌های دارای رزولوشن یکسان خودکار قابل تفکیک نیستند؛ انتخاب پروفایل صحیح مسئولیت کاربر است. هر پروفایل مستطیل مستقل دارد. رزولوشن متفاوت به خطا منجر می‌شود تا محدوده نادرست اعمال نشود.

تنظیمات در `config/settings.json` قابل ویرایش است. پیش‌فرض حساسیت بالا، ۸ نمونه در ثانیه، حداقل مساحت نسبی ۰٫۰۰۰۸ و مدت حرکت قوی ۰٫۵ ثانیه است. day_threshold و night_threshold آستانه تغییر روشنایی هستند؛ مقدار کمتر حساس‌تر است. برای کم‌کردن خطای شب، night_threshold یا min_area_ratio را با احتیاط افزایش دهید و نمونه‌های حرکت کوتاه را دوباره بررسی کنید. کاهش sample_fps سرعت را افزایش می‌دهد ولی احتمال ازدست‌رفتن حرکت کوتاه بیشتر می‌شود. تغییر تنظیمات یا ROI باعث بررسی مجدد فایل‌ها می‌شود. نسخه‌های قبلی خروجی برای حفاظت از نتایج حذف نمی‌شوند و ممکن است فضای بیشتری مصرف شود.

پردازش عمداً تک‌پردازشی است تا مصرف حافظه محدود باشد. فریم‌ها به‌صورت جریانی خوانده می‌شوند؛ فقط بهترین تصویر هر رویداد تا پایان کلیپ در حافظه باقی می‌ماند. فایل‌ها با اندازه، زمان تغییر، تنظیمات و پروفایل بررسی می‌شوند؛ تغییر محتوا با ثابت‌ماندن اندازه و زمان تغییر تشخیص داده نمی‌شود. برای توقف طولانی از Ctrl+C و اجرای مجدد استفاده کنید؛ رابط گرافیکی کامل یا توقف موقت درون برنامه وجود ندارد، مطابق درخواست ورودی ترمینال پیاده‌سازی شده است.

## بررسی صحت و محدودیت‌ها

```powershell
.\.venv\Scripts\python.exe -m unittest -v test_monitor.py
```

آزمون‌های مصنوعی برای تصویر ثابت، حرکت داخل و خارج محدوده، رویداد کوتاه، نویز ضعیف شب، فایل خراب و جست‌وجوی زیرپوشه‌ها ارائه شده‌اند. این آزمون‌ها در محیط تحویل اجرا نشده‌اند، چون مفسر پایتون موجود نبود. کپی، گزارش، اسکرین‌شات و ادامه پس از توقف باید در یک پوشه آزمایشی نیز بررسی شوند. برای بررسی حفظ اصل فایل می‌توانید هش فایل اصلی و کپی را با `Get-FileHash` مقایسه کنید.

قبل از پردازش آرشیو، چند کلیپ واقعی شامل حرکت روز، حرکت شب، چراغ خودرو، انعکاس، و کلیپ بدون حرکت را در پوشه آزمایشی بگذارید. این روش تضمین کشف تمام حرکات نیست؛ شخص کاملاً بی‌حرکت، رویداد کوتاه‌تر از فاصله نمونه‌ها، حرکت کم‌کنتراست، تاری شدید یا نور موضعی ممکن است خطا ایجاد کند. تغییر روشنایی شدید به REVIEW می‌رود. نتیجه NO_RELEVANT_MOTION اثبات نبود فعالیت نیست. آزمون نویز مصنوعی جای ارزیابی دوربین واقعی را نمی‌گیرد.

اگر ویدئو خوانده نمی‌شود، ابتدا آن را در یک پخش‌کننده بررسی کنید؛ برخی فرمت‌های اختصاصی DVR مانند DAV یا H264 خام با OpenCV قابل رمزگشایی نیستند. پشتیبانی وابسته به کدک نصب‌شده است. اگر گزارش ذخیره نشد، فایل Excel گزارش را ببندید و مجدداً اجرا کنید؛ وضعیت پردازش در SQLite باقی مانده است. در صورت خطای فضای دیسک، پس از آزادسازی فضا با --retry-failed اجرا کنید.

## ساخت فایل اجرایی ویندوز

```powershell
.\.venv\Scripts\python.exe -m pip install pyinstaller
.\.venv\Scripts\python.exe -m PyInstaller --onefile --name MotorcycleMonitor motorcycle_monitor.py
```

فایل `dist/MotorcycleMonitor.exe` را اجرا کنید. از گزینه `--windowed` استفاده نکنید چون دریافت مسیر از ترمینال انجام می‌شود. ساخت و آزمایش فایل اجرایی باید روی ویندوز مقصد انجام شود.
